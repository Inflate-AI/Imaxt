# Spec Delta

## Purpose

Defines the bidirectional mapping between an Imaxt block's EditorJS JSON data
and its MDX source representation, so content can move between a visual
EditorJS-based builder and git-diffable `.mdx` files losslessly.

## ADDED Requirements

### Requirement: Standalone blocks compile to their existing MDX syntax
Compiling a standalone block's EditorJS data to MDX SHALL produce the same
JSX-like component syntax already used for that block in hand-written Imaxt
MDX posts (the component name and prop names an existing Astro consumer
already expects), so generated posts require no change to how a site's
content pipeline reads them.

#### Scenario: Compiling a Statement block
- **WHEN** a Statement block's EditorJS data is compiled to MDX
- **THEN** the output is a `<Statement>` element whose attributes match that
  block's documented prop names and whose children contain its body content

### Requirement: Composite blocks compile to nested MDX markup
Compiling a composite block (`StatRow`, `Compare`, `Steps`, `Timeline`,
`Scrolly`, `CodeWalk`) to MDX SHALL produce the parent element containing one
child element per internal entry, in the same order as the block's internal
list, matching the existing nested MDX syntax for that block pair.

#### Scenario: Compiling a StatRow with three Stat entries
- **WHEN** a StatRow block's EditorJS data (with three internal Stat entries)
  is compiled to MDX
- **THEN** the output is a `<StatRow>` element containing three `<Stat>`
  child elements in the same order as the internal list

### Requirement: ImaxtCover compiles to post frontmatter
Compiling a post that has ImaxtCover data SHALL write that data into the
post's YAML frontmatter under its existing `cover` key shape, not into the
body's block list.

#### Scenario: Post with an ImaxtCover is compiled
- **WHEN** a post's ImaxtCover data is compiled to MDX
- **THEN** the output's frontmatter contains a `cover` entry with that data,
  and the body's block list contains no ImaxtCover element

### Requirement: Recognized MDX compiles back to the same block data
Parsing MDX source produced by this compiler for a given block SHALL recover
EditorJS block data deep-equal to the data that produced it, for every block
`block-render-engine` defines.

#### Scenario: Round-trip through MDX is lossless
- **WHEN** a block's EditorJS data is compiled to MDX and that MDX is then
  parsed back to block data
- **THEN** the recovered block data is deep-equal to the original

### Requirement: Unrecognized content is preserved, not dropped
Parsing MDX source that contains content other than a recognized Imaxt
component (plain prose, a heading, an unrelated JSX element) SHALL preserve
that content as a generic block rather than discarding it.

#### Scenario: Parsing a post with plain prose between blocks
- **WHEN** MDX source containing a paragraph of plain prose between two
  recognized Imaxt components is parsed
- **THEN** the resulting block list includes a block carrying that prose
  content, positioned between the two recognized blocks

### Requirement: Existing hand-written posts parse without data loss
Parsing MDX source that was hand-written before this compiler existed (using
the same existing component syntax, not previously generated by this
compiler) SHALL recover the same information content as a human reading that
source would, with no recognized Imaxt component silently dropped.

#### Scenario: Parsing a hand-written post
- **WHEN** a hand-written `.mdx` post using existing Imaxt component syntax
  is parsed
- **THEN** every recognized Imaxt component in that source appears as a
  corresponding block in the parsed output
